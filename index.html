A demo by Yossi Eliaz: the same Wordle RL environment from @adithya-s-k's RL_Envs_101, shown in four RL frameworks (OpenEnv, ORS, NeMo Gym, Verifiers), with code and a scripted sample rollout side by side.

The setup. @adithya_s_k reimplemented the same Wordle env across six RL frameworks as a Rosetta stone. I took four of those and gave each server its own islo.dev sandbox: OpenEnv and ORS came up; NeMo Gym hit a transient islo error on the first provisioning run (details); Verifiers runs in-process, so it needs no sandbox. Same env, four dialects.

The rollout transcripts below are canned (scripted in bin/rollout.py), not live LLM runs.

why per-sandbox

HF Spaces is fine for static demos. Cold per-trial sandboxes are the right shape for RL training-time env hosting: K parallel rollouts that can mutate state independently, per-trial isolation, the ability to ssh in to debug a hung env.

provision in one line

As run in May 2026 against RL_Envs_101 commit 41c04630. Upstream has since been renamed FineEnvs and restructured: on current main this env lives in 00-environments-101/envs/wordle/openenv, so use that path instead (not re-tested).

islo use rosetta-openenv \
  --source github://adithya-s-k/RL_Envs_101 \
  -- bash -c 'cd envs/wordle_env/openenv && uv venv .venv && . .venv/bin/activate \
              && uv pip install -e . \
              && setsid -f uvicorn server.app:app --host 0.0.0.0 --port 8080'

Adithya's Jupyter agent env (real Python code-exec) hard-depends on e2b-code-interpreter.
